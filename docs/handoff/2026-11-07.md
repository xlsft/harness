# Handoff: parallel work for xlsft`s harness sessions

Open work as of 2026-11-07 that nobody else has taken. Each task below is self-contained: give one task to one session,
each in its own worktree. They don't share files, except where a note says otherwise.

**Already taken, don't duplicate:**
- install script, Homebrew, `doctor`, completions, deep links
- Slack and phone dispatch
- import from Codex, Cursor and Gemini
- diagnostics: client logs, `/tools`, ArtifactPublish visibility
- agent inbox and project coordinator
- image generation (Settings > Images)
- enterprise packaging (`.pkg`, `.mobileconfig`, ADMX, offline mirror, dev containers)

**Not yet in `main`, don't build on them:**
- always-on hosts (branch `worktree-agent-a31c00e690bfe27e7`)
- VS Code extension (`worktree-agent-a9a1f5ee843fbb791`)
- Linux sandbox and PowerShell (being merged)

## Rules for every session

- **Naming:** in prose the product is always "xlsft\`s harness"; bare `harness` only in commands, paths and identifiers.
  Code, comments and docs in English.
- **Commits:** commit working increments on your own branch as you go, not only at the end. Record decisions in
  `docs/design/<topic>.md`. End commit messages with `Co-Authored-By: <model> <noreply@anthropic.com>`. Never push to `main`,
  tag, publish, force-push or rewrite history. Update with `git merge main`.
- **Where logic lives:** in the client (Go) and the server (core), not the frontend. UI strings go through `tt()`, then
  `node scripts/i18n-extract.mjs --apply` in `packages/ui`. Flat design with the existing tokens, no gradients.
- **Runtime sources:** nothing is read from `.claude/` or `CLAUDE.md` at runtime, only `.harness/` and `AGENTS.md`.
  Device-local settings never sync. Personal data stays visible to its owner only, never to admins.
- **Proto:**
  - Always run `buf format -w proto` with the `proto` path, then `buf generate`.
  - Use only your task's number range: SessionEvent `N`–`N+9`, UserPreferences and UpdateUserPreferencesRequest the two
    numbers given, relay Command and ManagedPolicy `N`–`N+9`.
- **Migrations:** `pnpm run db:generate`; a renumber on merge is expected.
- **Credentials:** no real accounts or tokens, except the Anthropic key configured on the server for task 1. Use fakes for
  every third-party service.
- **Processes and scratch files:** don't kill processes you didn't start. Scratch files get a unique prefix.
- **Tests:** targeted while working. At the end, one full client `go test -race ./...`, UI lint, typecheck and tests, and
  core tests. A failure that is only a timeout and passes alone is a flake; say so.
- **Final report:** what works, what ran only on fakes, what's left, branch and last commit.

## 3. Move a live session to an always-on host, and best-of-N

**Start only after the hosts branch is in `main`.** Ask the owner. Range 360.

- **Move a session:** a session running on the laptop can be moved to the user's always-on host.
  - Commit and push its worktree to a `harness/<id>` branch.
  - The host continues from the transcript and the same branch.
  - The laptop's copy becomes read-only with a link.
  - Refuse if the work has unpushable state, and say why.
- **Best-of-N:** start N attempts of one prompt on hosts or local worktrees, compare their diffs and test results side by
  side, and let the user keep one. The others' branches are deleted after confirmation.

## 4. Record a demo into a skill, and an iOS Simulator pane

Range 370, prefs 56–57.

- **Record a demo:** the user shows a workflow once on macOS: screen, clicks and keys, through the existing computer-use
  driver in recording mode, with the user's explicit start and stop.
  - It becomes a `SKILL.md` with steps, the apps used, and checks.
  - Screenshots are scrubbed and kept on the device.
  - Refuse to record password fields, and blank them.
- **Simulator pane:** a pane that streams a booted iOS Simulator (`simctl io screenshot` polling, or a faster path), with
  tap and type, plus tools for the agent to drive it.
- **Testing:** only on a simulator the session boots itself. Driving real apps needs the owner present; leave a checklist.

## 5. Telegram channel (inbound messages start or steer sessions)

Range 380.

- **Pattern:** follow the Slack integration's provider interface once it lands. Until then, design against the code-host
  bot (`packages/client/cibot`, `packages/core/src/relay`).
- **Bot:** a Telegram bot per user. The bot token is entered by the user and stored encrypted on the server; the chat is
  linked by a one-time code.
- **Behaviour:** messages start a session on the user's online machine or host, and replies steer it. Permission prompts
  come as inline buttons that only the owner can answer. Admins can turn it off in managed policy. Audit it.
- **Tests:** a fake Bot API.

## 6. Documents: images, OCR, conversion

Range 390.

- **Read first:** `docs/design/documents.md`. Tools are `DocumentRead` and `DocumentEdit` in `packages/client/documents`.
- **Add:**
  - Insert and replace images in docx and pptx.
  - Comment replies and resolved state in docx.
  - Table row operations in docx.
  - Adding text and images to PDF pages.
- **OCR for scanned PDFs:** a pure-Go or WASM engine with a permissive license; no GPL or AGPL.
- **Conversion:** docx↔pdf and pptx→pdf through LibreOffice, only where it is allowed to run. It can't run under the macOS
  sandbox: follow the existing `run_outside_sandbox` prompt.
- **Don't start LibreOffice in tests** unless `HARNESS_TEST_LIBREOFFICE=1`.
- **Clean-room:** don't read Anthropic's docx, pdf, pptx or xlsx skills.

## 7. Plugins that add UI panels

Range 400.

- **What:** a plugin can declare panes (an iframe page from the plugin folder) and status-bar items. They run in the same
  sandboxed iframe model as Visual (`packages/ui/app/lib/visual.ts`): CSP, no app access, a message API.
- **Message API:** read session state, send a prompt, open a file. Each capability is declared in the manifest and approved
  per device.
- **Policy:** admins can block plugin UI.
- **Also:** an example plugin in `catalog/` and docs.

## 8. Non-git VCS (hooks-based)

Range 410.

- **Read first:** `docs/design/core-gaps.md` explains the missing piece: worktree hook events and a hook stdout contract.
- **Build:** `WorktreeCreate` and `WorktreeRemove` hook events with that contract, so Mercurial, Jujutsu or Perforce users can
  provide isolation. Diff and status go through hooks with a documented JSON output.
- **Also:** a working jj example. Install jj only inside the session's own sandbox or a temp prefix, never system-wide.
