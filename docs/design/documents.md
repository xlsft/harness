# Document support (docx, xlsx, pptx, pdf)

Design notes and decisions, so the work can be continued from any commit. What a person must check by hand in real
Office applications is in [documents-compatibility.md](documents-compatibility.md).

## Clean-room

Everything here is designed from ECMA-376 (OOXML), ISO 32000 (PDF) and the documentation of the libraries we link.
Anthropic's `docx`, `pdf`, `pptx` and `xlsx` skills were not read, fetched or adapted, and must not be: their license
forbids copying and derivative works. All fixtures are generated by our own Go code from the specifications.

## Layout

| Where | What |
|---|---|
| `packages/client/documents` | The format code: no dependency on the tools or the session. Pure Go except the optional engine. |
| `packages/client/tools/document.go` | `DocumentRead` and `DocumentEdit`: read-before-write, rewind snapshot, atomic write, verification report. |
| `packages/client/server/sessiondiff_documents.go` | Semantic diff of documents in the Changes pane, on the disk and git paths. |
| `packages/client/skills/builtin_documents.md` | The `documents` skill, in our own words, embedded in the client and loaded only for judgement work. |
| `packages/core/prompts/tools/Document*` | Tool descriptions and schemas. |

## Tools

Two built-in tools, because built-in schemas cost tokens every session and one tool per operation would be about twenty:

- `DocumentRead` (`structure`, `read`, `search`, `check`, `render`, `fields`): read-only, in the read-tool permission list.
- `DocumentEdit` (`edit`, `create`, `merge`, `split`): in the edit-tool permission list.

Two tools rather than one because permission rules, plan mode and accept-edits all work per tool name.

Every write has one target, `file_path`, so the permission check sees the whole effect. That is why `split` writes one
output per call, and why `merge`/`split` sources must have been read first (reading them passed the read check).

## Tiers

- **Pure Go, always there:** reading, search, editing, package and format checks, form filling, page operations, creation.
  Builds keep `CGO_ENABLED=0`.
- **Optional engine:** rendering, and recalculation of formulas beyond the built-in evaluator. When something is missing the
  tool says "not available" and the check counts as "could not verify"; it never reports a pass.

### Engine choice

- **LibreOffice found on the machine** (`soffice` on PATH or in the usual install places) converts Office files to PDF and
  recalculates workbooks. It is a separate process we never link, so its MPL license does not reach us. It runs on a
  temporary copy, with its own profile directory, macros off and link updates off. Tests that start the real program are
  behind `HARNESS_TEST_LIBREOFFICE=1`; by default they use a fake script, so a test run never launches it.
- **LibreOffice does not run under the macOS sandbox.** Traced under the Seatbelt profile of `sandbox/seatbelt.go`
  (LibreOffice from Homebrew's cask, November 2026): it aborts at start (SIGABRT, `abort() called`), denied the Mach
  services `com.apple.windowserver.active`, `com.apple.coreservices.launchservicesd`, `com.apple.tccd.system`,
  `com.apple.pasteboard.1`, `com.apple.distributed_notifications@Uv3`, then `com.apple.CARenderServer`, plus
  `file-issue-extension`. Allowing the window server alone still aborts; allowing LaunchServices alone hung for over three
  minutes and was stopped. We did not widen the profile: LaunchServices is exactly what lets a process start things
  outside the sandbox. Each failed launch also leaves a crash report, and one was followed by a plain `soffice` under
  launchd, so the engine must not even try.
  **Decision:** with the sandbox active on macOS the engine reports "not available" without starting anything. A call may
  pass `run_outside_sandbox`, which goes through the same user-only prompt as Bash's (`PermissionHints`, checked as a
  `soffice` command, and a policy can refuse it); then it runs unconfined, on a temporary copy with its own profile. With
  the sandbox off it runs as any local program would. Reads, edits and format checks do not need it. Where a future
  platform has a sandbox driver, the engine runs under it through `Engine.Confine`, untested there.
- **PDFium through WebAssembly** (`github.com/klippa-app/go-pdfium` MIT, PDFium Apache-2.0/BSD, `wazero` Apache-2.0)
  rasterises PDF pages without CGO. It is embedded, so PDF pages render even without LibreOffice. The first start
  compiles the module (about 20 s on an M-series Mac); the compiled code is cached under the user's cache directory, so
  later starts are fast. It only ever starts for a `render`.
- Rejected: Poppler (GPL) and MuPDF (AGPL) cannot be linked. `pdfcpu` (already a dependency, Apache-2.0) does the page and form work.

## Addressing

An address is an ID plus an 8-hex content fingerprint, both from `structure`, `read` or `search`:

| Format | ID | Fingerprint covers |
|---|---|---|
| docx | `document:p12`, `header1:p0`, `footnotes:p3`: story part and ordinal of the paragraph | the paragraph's XML bytes |
| xlsx | `Sheet1!B2` | the cell's XML bytes (an empty cell has a fixed value) |
| pptx | `s256/sp4`: the slide's `sldId` (survives reordering) and the shape's `cNvPr` id | the shape's XML bytes |
| pdf | page numbers; form fields by full name | not needed: page operations are whole-file and refuse on any change since read |

Rules:

- Batch edits resolve every target against the file as it is, then apply together: no address shifts inside a batch.
- A fingerprint mismatch is refused with the current text and fingerprint, unless exactly one paragraph or shape of the
  same story now has that fingerprint (an earlier insert shifted the ordinal): then it is followed and reported.
- More than one match, for a `find` or a fingerprint, is refused with the candidates.
- The tool also goes through read-before-write tracking: the file must have been read and not changed since.

## Editing

Only the parts that change are rewritten: other zip entries are copied with `zip.Writer.Copy`, compressed bytes and
headers intact, in their order. Inside a changed part only the changed element's bytes are spliced, as `tools/notebook.go`
does, so XML the code does not understand survives. We never round-trip through a library.

Writes are atomic (temp file in the same directory, fsync, rename). Zip limits: entry count, total and per-part
uncompressed size, compression ratio, enforced on the real bytes rather than the declared sizes. DOCTYPE is refused.

The rewind snapshot must succeed first: `Env.BeforeEditChecked` returns the error of `FileHistory.TrackEditChecked` and
the edit is refused. `FileHistory` writes backups and restores files atomically now, for all tools.

## Verification

Runs automatically on a temporary copy, before the user's file is replaced. Findings are compared with those of the
original by a stable key and fall into three states: **new**, **inherited**, **could not verify**. New errors refuse the
edit; new warnings are reported with the written file. Each report says a passing check does not prove Office opens the
file. Rendering runs only on request.

## Decisions per format

See the operation list in the tool description (`packages/core/prompts/tools/DocumentEdit/description.md`).

- docx, mixed formatting: replaced text inherits the formatting of the first run the match touches; when the matched runs
  differ, the report says so. A match may not cross a hyperlink, field or tracked-change boundary.
- docx, tracked changes: an edit is tracked when `w:trackRevisions` is set in the document's settings, unless the call says
  `track: false`; `track: true` forces it. Addresses and text use the view with insertions shown and deletions hidden
  (deleted text is listed separately); `read` marks both.
- xlsx: no row or column insertion in this version. Editing the master of a shared formula, array formulas, merged
  non-anchor cells, table header cells and protected sheets is refused. Strings go in as inline strings, leaving the
  shared-string table alone. Removing a formula also removes `calcChain.xml`, which Excel rebuilds. `fullCalcOnLoad` is
  set when a formula input changes, and dependents get computed values when the built-in evaluator can compute them.
- pptx: slide add, delete and move are atomic. A cloned slide shares layouts and media, loses its notes, and deep-copies
  charts and embedded objects, with a warning.
- pdf: page-level and form fields only. XFA, signed and encrypted files are reported and refused. Flat-form overlay and OCR are later.

## The skill

Built in rather than a `catalog/` plugin: the tool descriptions point to it and it must be there without an install. It is
embedded, ranks below every other source, so a user's own `documents` skill replaces it, and costs only its name and
description until loaded. A `.claude` path is not involved.

## Changes pane

`server/sessiondiff_documents.go` projects both versions with `Document.Project` and diffs the lines. Projection lines hold
no ordinals, so an inserted paragraph is one added line. Limits: `maxDocumentDiffBytes` per file, `maxDocumentDiffLines` per
side. Results go through the existing `diffCache`, since the totals are measured after every tool. A version that cannot be
read shows as binary. No contract changed: hunks carry the header `compared by content`, and `DiffPane.vue` knows the
extensions. Rewind goes through the existing file history.

## Tests

- Fixtures are generated in Go from the specifications (`documents/fixtures_test.go`, `documents/create.go`), never copied.
- A default test run starts no real LibreOffice and no PDFium. `HARNESS_TEST_LIBREOFFICE=1` and `HARNESS_TEST_PDFIUM=1` turn on
  the real ones (`-run Real`). Tools that reach the engine replace `documents.FindSoffice` with a fake.
- `evals/tasks/doc-*` grade with Python's standard library alone and need no model to self-test.
- [documents-compatibility.md](documents-compatibility.md) lists what only a person with Office can check.

## Left for later

- Row and column insertion in sheets (excluded by design), and writing past `MaxXMLNodes`: very large sheets are refused, not streamed.
- docx: nested comment replies and resolved state, table row operations, images. Moves and row-level tracked changes are refused and left to Word. Rejecting formatting changes is refused.
- xlsx: data validation is listed but not enforced on written values. Structured references and other workbooks are not traced: the report counts such formulas. The evaluator covers common functions; others report "unknown".
- pptx: images and charts cannot be added; shapes in groups cannot be moved. Clones are tested with a chart and a workbook, not SmartArt or media.
- pdf: flat-form overlay, OCR, adding content to pages. Created PDFs hold Latin-1 only.
- Conversion between formats, and pages from an engine other than LibreOffice.
