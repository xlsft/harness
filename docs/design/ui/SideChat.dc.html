…I'm taking ConnectRPC because it stays gRPC-compatible and works over HTTP/1.1 and from the browser. Why ConnectRPC and not plain gRPC here?

Three reasons specific to harness:

1Nitro serves fetch handlers over HTTP/1.1, and plain gRPC needs HTTP/2 end to end.
2The web and mobile UI can call Connect directly, no gRPC-Web proxy.
3It's still wire-compatible, so the Go client can speak gRPC if it ever needs to.

The cost is bidi streaming: browsers can't do it, so the relay sticks to server streams.
